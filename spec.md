# Техническая спецификация: mail_messanger

## 1. Назначение

Фоновый сервис, который подключается к почтовому ящику на сервере mailcow по протоколу IMAP, отслеживает появление новых писем и отправляет о каждом из них уведомление в чат Telegram через Bot API.

## 2. Окружение и зависимости

| Компонент | Версия |
|---|---|
| Python | 3.13 (виртуальное окружение `.venv`) |
| IMAPClient | 3.0.1 — IMAP-клиент с поддержкой IDLE |
| python-dotenv | 1.0.1 — чтение `.env` |
| requests | 2.32.3 — HTTP-запросы к Telegram Bot API |

Разбор писем выполняется стандартной библиотекой (`email`, `html`, `re`).

Внешние системы:

- **Почтовый сервер:** `mail.cert.gov.kg` (mailcow, Dovecot), IMAPS-порт 993, поддерживает `IDLE`.
- **Telegram Bot API:** `https://api.telegram.org/bot<токен>/…`, методы `getMe` и `sendMessage`.

## 3. Структура проекта

```
mail_messanger/
├── .env                    # параметры подключения (не публикуется)
├── state.json              # прогресс обработки, создаётся при первом запуске
├── main.py                 # точка входа из корня: python main.py [--check]
├── requirements.txt
├── Dockerfile              # образ на python:3.13-slim, STATE_FILE=/app/data/state.json
├── docker-compose.yml      # сервис mail-notifier: env_file .env, том для state.json
├── .dockerignore           # .env, .venv, state.json и прочее не попадают в образ
├── README.md               # краткая инструкция по запуску
├── spec.md                 # этот документ
├── CLAUDE.md               # заметки для Claude Code
└── mail_notifier/          # пакет приложения
    ├── __init__.py         # PROJECT_ROOT — корень проекта (путь к .env и state.json)
    ├── __main__.py         # слой запуска: CLI, логирование, сигналы, режим --check
    ├── config.py           # слой конфигурации: Config.from_env()
    ├── watcher.py          # слой IMAP: подключение, IDLE, отбор и загрузка новых писем
    ├── state.py            # слой хранения: State (state.json)
    ├── parser.py           # слой разбора писем: заголовки, текст, вложения
    ├── notification.py     # слой представления: текст уведомления в HTML для Telegram
    └── telegram.py         # слой доставки: клиент Bot API с повторами
```

### 3.1. Слои и зависимости между ними

```
__main__ ──► config
   │
   └──► watcher ──► state
           │
           ├──► notification ──► parser
           │
           └──► telegram
```

Зависимости направлены только сверху вниз. `parser`, `notification`, `state` и `telegram` не знают об IMAP и друг о друге (кроме `notification → parser`), поэтому их можно тестировать изолированно.

| Модуль | Ответственность | Основные объекты |
|---|---|---|
| `__main__.py` | Разбор аргументов, настройка логирования, обработка SIGTERM/Ctrl+C, диагностика `--check` | `main()`, `check()` |
| `config.py` | Чтение `.env`, проверка обязательных параметров, значения по умолчанию | `Config`, `env_bool()` |
| `watcher.py` | Жизненный цикл IMAP-соединения, ожидание событий, отбор новых UID, загрузка писем, переподключение | `connect()`, `MailWatcher`, `MAX_BODY_FETCH` |
| `state.py` | Сохранение `uidvalidity` и `last_uid` между запусками (атомарная запись) | `State` |
| `parser.py` | Декодирование MIME-заголовков, извлечение текста (plain или HTML→текст) и имён вложений | `decode_str()`, `format_addresses()`, `extract_body()` |
| `notification.py` | Сборка текста уведомления с экранированием HTML и ограничением длины | `build_notification()`, `HEADERS_ONLY` |
| `telegram.py` | Отправка сообщений с повторами и классификацией ошибок | `Telegram`, `TelegramError`, `TelegramUnavailable` |

## 4. Конфигурация (`.env`)

Файл читается из корня проекта (`PROJECT_ROOT / ".env"`). Переменные окружения процесса имеют приоритет: python-dotenv не перезаписывает уже заданные значения.

### 4.1. Обязательные параметры

| Параметр | Назначение |
|---|---|
| `TELEGRAM_API` | Токен бота **или** полный URL `https://api.telegram.org/bot<токен>` (оба формата поддерживаются) |
| `TELEGRAM_CHAT_ID` | ID чата-получателя (для групп и каналов — отрицательное число вида `-100…`) |
| `EMAIL_HOST` | Хост почтового сервера (используется для IMAP, если не задан `IMAP_HOST`) |
| `EMAIL_HOST_USER` | Логин почтового ящика |
| `EMAIL_HOST_PASSWORD` | Пароль почтового ящика |

Если чего-то не хватает, сервис завершается с сообщением `В .env не заданы обязательные параметры: …`.

### 4.2. Необязательные параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `IMAP_HOST` | `EMAIL_HOST` | Хост IMAP |
| `IMAP_SSL` | `true` | `true` — неявный TLS (IMAPS), `false` — открытое соединение с обязательным STARTTLS |
| `IMAP_PORT` | `993` (или `143` при `IMAP_SSL=false`) | Порт IMAP |
| `IMAP_USER` / `IMAP_PASSWORD` | `EMAIL_HOST_USER` / `EMAIL_HOST_PASSWORD` | Отдельные учётные данные для IMAP |
| `IMAP_FOLDER` | `INBOX` | Отслеживаемая папка |
| `IMAP_IDLE_TIMEOUT` | `300` | Сколько секунд ждать в одном цикле IDLE |
| `IMAP_POLL_INTERVAL` | `60` | Интервал опроса в секундах, если сервер не поддерживает IDLE |
| `STATE_FILE` | `<корень>/state.json` | Путь к файлу состояния |
| `LOG_LEVEL` | `INFO` | Уровень логирования (`DEBUG` также выводит ответы IDLE) |

Логические значения: `1`, `true`, `yes`, `on` (без учёта регистра) — истина, всё остальное — ложь.

### 4.3. Параметры, которые не используются

`EMAIL_PORT=587`, `EMAIL_USE_TLS` и `EMAIL_USE_SSL` относятся к **отправке** почты (SMTP, формат настроек Django) и сервисом игнорируются. Порт 587 для IMAP не подходит.

## 5. Алгоритм работы

### 5.1. Запуск

1. `main()` настраивает логирование и загружает `Config`.
2. Создаётся клиент `Telegram`, регистрируется обработчик SIGTERM.
3. Вызывается `MailWatcher.run_forever()`.

### 5.2. Сессия IMAP (`MailWatcher.session`)

1. **Подключение** (`connect`): TLS через `ssl.create_default_context()` (сертификат проверяется), таймаут сокета 60 с, затем `LOGIN`.
2. **Открытие папки** (`open_folder`): `SELECT` с флагом `readonly=True`.
   - Если `UIDVALIDITY` сервера не совпадает с сохранённым (первый запуск или пересоздание ящика), `last_uid` становится равным `UIDNEXT − 1` (если `UIDNEXT` нет — максимальному UID из `SEARCH ALL`). Старые письма **не отправляются**.
3. **Начальная проверка** (`process_new`): обрабатываются письма, пришедшие, пока сервис не работал.
4. **Цикл ожидания:**
   - Если сервер поддерживает IDLE: `IDLE` → `idle_check(timeout=IMAP_IDLE_TIMEOUT)` → `DONE`.
   - Если нет: `sleep(IMAP_POLL_INTERVAL)` → `NOOP`.
   - После каждого цикла (и по событию, и по таймауту) вызывается `process_new`. Это же поддерживает соединение и страхует от пропущенных IDLE-уведомлений.

### 5.3. Обработка новых писем (`process_new`)

1. `UID SEARCH UID <last_uid+1>:*`. По RFC 3501 диапазон `N:*` всегда включает максимальный UID, даже если он меньше `N`, поэтому результат дополнительно фильтруется: `uid > last_uid`.
2. Для всех найденных UID одним запросом загружаются `RFC822.SIZE` и `BODY.PEEK[HEADER]`.
3. По каждому UID в порядке возрастания:
   - Письмо до `MAX_BODY_FETCH` (5 МБ) загружается целиком (`BODY.PEEK[]`).
   - Письмо больше этого размера разбирается только по заголовкам и получает служебный заголовок `X-Headers-Only`.
   - Если письмо удалили между `SEARCH` и `FETCH`, оно пропускается.
   - Собирается уведомление, затем `Telegram.send`.
   - `last_uid = uid`, затем `state.save()` — после **каждого** письма.

Везде используется `PEEK`, а папка открыта только для чтения, поэтому флаг `\Seen` никогда не ставится.

### 5.4. Переподключение (`run_forever`)

При любой ошибке сессии (`IMAPClientError`, `OSError`, `socket.timeout`, `ssl.SSLError`, `TelegramError`) ошибка логируется и через паузу выполняется повторное подключение. Пауза растёт 5 → 10 → 20 → … → 300 с и сбрасывается до 5 с, если предыдущая сессия проработала больше 5 минут.

### 5.5. Завершение

Ctrl+C или SIGTERM поднимают `KeyboardInterrupt`; `session()` в блоке `finally` выполняет `LOGOUT`, в лог пишется «Остановлено», процесс возвращает код 0.

## 6. Хранение состояния (`state.json`)

```json
{"uidvalidity": 1700000000, "last_uid": 1234}
```

- `uidvalidity` — значение `UIDVALIDITY` папки. UID имеют смысл только вместе с ним.
- `last_uid` — UID последнего обработанного письма.
- Запись атомарная: сначала `state.tmp`, затем `replace`.
- Если файл повреждён, выводится предупреждение и сервис ведёт себя как при первом запуске.
- Удаление `state.json` сбрасывает прогресс: уведомления пойдут только о письмах, пришедших после следующего запуска.

## 7. Гарантии доставки

| Ситуация | Поведение |
|---|---|
| Сервис был остановлен, пришли письма | При запуске придут уведомления обо всех пропущенных письмах |
| Обрыв IMAP-соединения | Переподключение; письма, обработанные до обрыва, повторно не отправляются |
| Telegram недоступен (сеть, 5xx, исчерпаны повторы) | `TelegramUnavailable`: `last_uid` **не** сдвигается, сессия перезапускается, письмо отправляется повторно |
| Telegram отклонил сообщение (4xx, кроме 429) | `TelegramError`: ошибка в логе, письмо **пропускается**, чтобы не зациклиться |
| Telegram вернул 429 (лимит) | Ожидание `retry_after + 1` с и повтор |
| Падение процесса между `send` и `save` | Возможен один дубль уведомления (семантика «как минимум один раз») |

## 8. Telegram

- Метод: `POST /sendMessage`, JSON `{chat_id, text, parse_mode: "HTML", disable_web_page_preview: true}`, таймаут 30 с.
- Повторы: до 5 попыток при сетевых ошибках и 5xx с паузой `min(2^n, 60)` с; при 429 — по `retry_after`.
- `--check` вызывает `GET /getMe` (таймаут 15 с), сообщения не отправляются.
- Требования: токен действителен, бот добавлен в чат `TELEGRAM_CHAT_ID` и может в нём писать.

### 8.1. Формат уведомления

```
📧 Новое письмо [(папка), если не INBOX]
От: Имя <адрес>
Кому: адреса                       — если есть
Тема: тема | (без темы)
Дата: ДД.ММ.ГГГГ ЧЧ:ММ             — в локальном часовом поясе сервера, где запущен сервис
📎 Вложения: имена файлов          — если есть
Письмо слишком большое, текст не загружен.   — для писем > 5 МБ

┃ начало текста письма (до 700 символов, «…» при обрезке)
```

- Все значения из письма экранируются `html.escape`, чтобы не нарушить HTML-разметку Telegram.
- Длина фрагмента ограничена так, чтобы сообщение уложилось в лимит Telegram в 4096 символов.

## 9. Разбор писем (`parser.py`)

- Заголовки декодируются из MIME encoded-words (`=?utf-8?b?…?=`); при ошибке декодирования возвращается исходная строка.
- Адреса: `Имя <адрес>` или только адрес; несколько адресов перечисляются через запятую.
- Текст: берётся первая часть `text/plain`. Если её нет или она пустая — первая `text/html`, из которой удаляются `script`/`style`/`head` и теги, `<br>`/`</p>`/`</div>` заменяются переводами строк, HTML-сущности раскодируются.
- Кодировка части берётся из `charset` (по умолчанию UTF-8); неизвестная кодировка или битые байты заменяются, а не вызывают ошибку.
- Вложение — любая часть с именем файла или `Content-Disposition: attachment`; безымянные помечаются «без имени».
- Пробелы схлопываются, подряд идущие пустые строки сводятся к одной.

## 10. Запуск и эксплуатация

```
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py --check     # диагностика, код возврата 0/1
.venv\Scripts\python.exe main.py             # рабочий режим (или: python -m mail_notifier)
```

Режим `--check` проверяет `getMe` в Telegram, а также вход в IMAP и открытие папки. Он выводит число писем и наличие IDLE, ничего не отправляет и не меняет `state.json`.

Запуск в Docker:

```
docker compose run --rm mail-notifier python main.py --check
docker compose up -d --build
```

Образ не содержит `.env`: переменные передаются через `env_file` в `docker-compose.yml`, а `load_dotenv` внутри контейнера ничего не находит и не мешает. Переменная `STATE_FILE` в образе указывает на `/app/data/state.json`; каталог `/app/data` подключён к именованному тому `mail-notifier-data`, так что состояние переживает пересоздание контейнера (атомарная запись через `.tmp` идёт в тот же каталог). Процесс работает от непривилегированного пользователя `app`; `docker stop` посылает SIGTERM, который обрабатывается штатно (§5.5). Политика `restart: unless-stopped` отвечает за автозапуск.

Логи пишутся в stderr в формате `ГГГГ-ММ-ДД ЧЧ:ММ:СС,мс УРОВЕНЬ сообщение`. Для работы в фоне сервис можно запустить как службу Windows (например, через NSSM или Планировщик заданий) или как unit systemd на Linux: перезапуск внутри процесса уже предусмотрен, менеджер служб нужен только для автозапуска.

## 11. Безопасность

- Соединения с IMAP и Telegram идут только по TLS с проверкой сертификатов.
- Учётные данные хранятся только в `.env` и в логи не выводятся (логируются хост, порт и логин, но не пароль и не токен).
- Сервис открывает ящик только для чтения и ничего в нём не меняет.
- В Telegram передаются отправитель, получатели, тема и начало текста письма — это нужно учитывать при выборе чата-получателя.

## 12. Ограничения

- Отслеживается одна папка одного ящика.
- В лучшем случае доставка ровно один раз, в худшем — как минимум один раз (см. раздел 7).
- Письма, отклонённые Telegram с ошибкой 4xx, повторно не отправляются.
- Автотестов и линтера в проекте нет.
